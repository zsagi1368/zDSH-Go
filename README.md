**zDSH-Go is an AI development environment** that lets you chat with an AI in your browser and have the AI write code and take care of tasks. It is an enhanced edition of [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness), with context cache management integrated on top so the AI can better remember what was said in the conversation.

> **Note:** This project is currently in _developer preview_ and may introduce compatibility-breaking changes. Read the [safety notice](SAFETY.md) before running it.

## Quick start

### What you need

| Tool | Version requirement | How to install it |
|---|---|---|
| **Node.js** | v22.19 or later (v23 is not supported) | Download the LTS version from [nodejs.org](https://nodejs.org/) |
| **pnpm** | v11 or later | Run `corepack enable pnpm` after installing Node.js |
| **Git** | any recent version | Download it from [git-scm.com](https://git-scm.com/) |

### Install (once)

**Windows users (PowerShell):**

```powershell
git clone https://github.com/zsagi1368/zDSH-Go.git
cd zDSH-Go
.\install.cmd
```

**macOS / Linux users (terminal):**

```bash
git clone https://github.com/zsagi1368/zDSH-Go.git
cd zDSH-Go
./scripts/install.sh
```

The install script does it all for you: it checks the environment, installs dependencies, builds the project, and creates the data directory. No manual steps are needed.

### Run

Load the environment before each use, then start:

**Windows (PowerShell):**

```powershell
. .\env.ps1
dsh web
```

**macOS / Linux (terminal):**

```bash
source ./env.sh
dsh web
```

After it starts, it opens your browser automatically and shows the AI chat interface. The default address is `http://127.0.0.1:3080`.

> **Tip:** If the browser does not open automatically, just visit `http://127.0.0.1:3080` yourself. Add the `--no-open` flag to skip opening the browser.

### Upgrade

When a new version is available, it only takes two steps:

```bash
git pull
.\install.cmd    # Windows 用户
# 或
./scripts/install.sh    # macOS / Linux 用户
```

Your conversation history and data are kept and will not be lost.

### Uninstall

**Windows (PowerShell):**

```powershell
.\uninstall.cmd
```

**macOS / Linux (terminal):**

```bash
./scripts/uninstall.sh
```

By default, only project files are deleted and your data is kept. If you want to delete all data completely (including conversation history), add the `--purge` flag.

## FAQ

**Q: What is the difference between the installer and running from source?**
A: None. The installer only runs `pnpm install` and `pnpm run build` for you, and then generates the `env.ps1`/`env.sh` environment files. Both ways run the same program.

**Q: I have already used the installer — can I still run it through pnpm?**
A: Yes, the two coexist. The `env.ps1`/`env.sh` files generated by the installer do not conflict with `pnpm dsh web`.

**Q: Will upgrading lose my conversation history?**
A: No. `git pull` only updates the code; your data lives in the `data/` directory and will not be touched by the upgrade.

**Q: Will uninstalling delete my conversation history?**
A: Not by default. The default only deletes project files (node_modules, build output, and so on). Adding `--purge` is what deletes the entire project directory (including the data).

**Q: Can I install the official DeepSeek Harness and zDSH-Go at the same time?**
A: Yes. Their data directories do not interfere with each other: the official release uses `~/.dsh`, and zDSH-Go uses the `data/` directory inside the project.

**Q: Where is my data stored?**
A: All data lives in the `data/` folder under the project directory, including conversation history, plugin configuration, model settings, and so on. Nothing is written outside the project directory.

### Context cache management

zDSH-Go integrates context cache management at the core source level instead of mounting it as a plugin. This means:

- Every request path (agent loop, session handling, tool calls, token metering, model slots, compaction) takes part in a unified cache lifecycle
- A subagent's initial prompt carries a runtime context snapshot
- File reads and search results expose `l3.pruning` metadata
- There is a standing budget gate script, `scripts/verify-budget-table.ts`

### Factory plugins

On first start, zDSH-Go automatically installs 8 factory plugins (6 enabled by default, 2 skipped by default):

| Plugin | What it does | Enabled by default |
|---|---|---|
| `dsh-webstack` | Web search tools | Yes |
| `dsh-webstack-bridge` | Webstack data bridge | Yes |
| `dsh-omnivision` | Vision capabilities | Yes |
| `dsh-filehub` | File management | Yes |
| `dsh-plugin-center` | Plugin management center | Yes |
| `zdsh-workbench` | IDE-grade workbench (files / editor / terminal / git / tasks) | Yes |
| `dsh-webstack-verticals` | Vertical-domain pack | No (enable on demand) |
| `dsh-autopilot` | Automation tasks | No (enable on demand) |

### Configuration

The installation is self-contained: all data lives in the `<repo>/data` directory, and nothing is written outside the project directory.

| Variable | Points at | Default |
|---|---|---|
| `DSH_HOME` | Main data directory | `<repo>/data` |
| `DSH_BRANCH_HOME` | Governance data (plugin registry, approval ledger, installed plugins) | `<repo>/data/zdsh` |
| `DSH_AGENTS_HOME` | Official skills directory | `<repo>/data/agents` |

### Security

- **Data isolation** — the self-contained layout keeps all data under `<repo>/data`
- **Official isolation** — the official release's data lives in `~/.dsh`, and zDSH-Go never writes to it
- Read the [safety notice](SAFETY.md) before running
